# Host-side gcb push

`gcb push` deliberately reverses the old "the broker does not proxy Git" rule for one operation.

- The container owns the checkout and commits; the host owns the credentials.
- The request carries an allowlisted repository, remote, branch, exact commit, optional
  force/lease expectation, account and proxy.
- The host rebuilds the URL and runs `git push` from a scratch bare repository whose alternates
  point at the shared object store, so container config and hooks are not loaded. Rebuilding the
  URL is what prevents a changed `.git/config` from redirecting the push.
- Git's credential helper has no push delegation, so this is an explicit `gcb push`, not a
  transparent interception of `git push`.
- The container's own `pre-push` hook runs in the container; the host never runs container hooks.
- SSH uses host-controlled aliases (`sshAccounts`) and their keys/ports/proxies.
- The allowlist is destination authorization, not proof of the commit's source; provenance remains
  the separate issue #138.

## Source provenance

The allowlist authorizes the destination, not the source. The host pushes an exact commit from the
container-writable checkout, so it cannot prove the commit belongs to the named repository; ordinary
`git push` has the same property. A host-owned clone is the way to establish checkout provenance;
commit signatures establish who signed the object, not where it was created. Neither is a check over
the container's `.git/config`.
