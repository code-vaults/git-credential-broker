# Host image and the gh version

The action executor runs `gh` as the App. The image needs a current `gh`; the base image's package
manager is not the only place it can come from.

Measured on 2026-10-26:

- `node:24-slim` is Debian bookworm; its apt candidate for `gh` is **2.23.0**;
- `node:24-alpine` + `apk add github-cli` gives **2.97.0**;
- GitHub CLI's stable apt repository gives **2.103.2**.

Debian bookworm freezes feature versions; its `gh` will not become 2.103 through `apt-get update`.
Alpine is closer but also behind. The image therefore uses `node:24-slim` and installs `gh` from the
GitHub CLI stable apt repository.

The Debian packages still come from the configured Debian mirror (Aliyun by default here, overridable
with `--build-arg APT_MIRROR=…`); only `gh` comes from GitHub's repository. The archive keyring at
`/usr/share/keyrings/githubcli-archive-keyring.gpg` is the public key apt uses to verify that
repository.

`gh` is not version-pinned: it is a system tool, and the stable apt repository's candidate is the
version the image builds with. This is different from the Debian package, whose frozen 2.23.0 is too
old for the action catalog.
